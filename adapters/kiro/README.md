# Kiro adapter

Installs Corporate Agent OS into a Kiro IDE (1.x) or Kiro CLI (v3) workspace. Formats verified against kiro.dev documentation on 2026-11-18 (see `research/source-register.md` S5–S12).

## What is shipped

| Component | Source here | Installed to | Kiro feature |
|---|---|---|---|
| Skills | `../../skills/` | `.kiro/skills/<name>/` | Agent Skills (`/skill-name`, auto-activation) |
| Custom agents | `agents/*.md` (generated) | `.kiro/agents/<id>.md` | Custom agents, usable as primary agent or sub-agents |
| Steering | `steering/corporate-agent-os.md` | `.kiro/steering/` | Steering with `inclusion: always` |
| Hooks | `hooks/corporate-agent-os-guards.json` | `.kiro/hooks/` | Hooks v1 (two validators disabled by default, one Stop reminder enabled) |
| Project validators | `../../scripts/validate/` (subset) | `.corporate-agent-os/validators/` | Used by the hooks |
| Power | `plugin.template.json` → `../../powers/kiro/corporate-agent-os/` | Kiro Powers panel | Agent Plugins 1.0.0 power (skills only) |

`agents/` is generated by `python scripts/package/build_adapters.py` from `agents/**/*.yaml`. Do not edit the generated files.

## Install

```bash
python scripts/install/install.py --target kiro --destination /path/to/project --dry-run
python scripts/install/install.py --target kiro --destination /path/to/project
```

Then in Kiro: open the workspace, trust it (workspace agents load only in trusted workspaces), open the agent selector and choose `corporate-orchestrator`, or ask the default agent to "use the corporate-orchestrator agent".

To install the Power instead of (or in addition to) workspace skills: **Powers → Add Custom Power → Import power from a folder** and select `powers/kiro/corporate-agent-os/`. Do not install both the Power and `.kiro/skills/` copies of the same skills unless you want them listed twice.

## How the generated agents use Kiro features

- `tools`: `read`, `write`, `shell`, `web` category tags; orchestrator and department leads list `subagent/<agent-id>` entries so they can only spawn the agents they are meant to.
- `resources`: `skill://.kiro/skills/<skill>/SKILL.md` for each skill the agent loads (custom agents do not load skills by default) and `file://.kiro/steering/corporate-agent-os.md`.
- `permissions.rules`: `fs_write` allow rules from the agent's `write_scope`; shell allow/ask/deny lists from `core/permissions/policy.yaml`; `subagent` rules with `effect: ask` so you see each delegation. Deny rules win across scopes; the parent session's policy also applies to sub-agents.
- `welcomeMessage`: tier and autonomy so you know what you switched to.

## Enabling the validation hooks

The two `PostFileSave` hooks call the project-side validators installed under `.corporate-agent-os/validators/`. They are shipped `enabled: false` because they require Python 3.10+ with PyYAML on the PATH Kiro uses. Set `"enabled": true` in `.kiro/hooks/corporate-agent-os-guards.json` after checking `python -c "import yaml"` works.

## Limits

- Kiro has no built-in browser tool; design QA screenshots need an MCP server (for example a Playwright MCP) configured in `.kiro/settings/mcp.json` and added to the relevant agent's `tools` (`@<server>`). An example is in `mcp.example.json`.
- Path-scoped write permission is enforced through `fs_write` matchers; a write outside the match prompts rather than being silently denied unless you add a deny rule.
- Sub-agent review loops exist in Kiro (trigger text, `max_iterations` 1–10) but the DAG is planned up front and cannot change mid-run; the orchestrator plans the whole workflow before delegating.
- Kiro Web and Mobile can use project agents as sub-agents but cannot select one as the primary session agent.
