# Codex CLI adapter

Installs Corporate Agent OS skills and repository instructions for OpenAI Codex (CLI and IDE extension). Formats verified against the Codex skills documentation on 2026-11-18 (`research/source-register.md` S16).

## What is shipped

| Component | Source here | Installed to | Codex feature |
|---|---|---|---|
| Skills | `../../skills/` | `.agents/skills/<name>/` | Skills (`$skill-name`, implicit matching by description) |
| Repository instructions | `AGENTS.md` (generated) | `AGENTS.md` (or `CORPORATE-AGENT-OS-AGENTS.md` if one exists) | AGENTS.md |
| Project validators | `../../scripts/validate/` (subset) | `.corporate-agent-os/validators/` | Run manually |

`AGENTS.md` is generated by `python scripts/package/build_adapters.py`; it contains the role table derived from `agents/**`.

## Install

```bash
python scripts/install/install.py --target codex --destination /path/to/project --dry-run
python scripts/install/install.py --target codex --destination /path/to/project
```

User scope (`~/.agents/skills`) with `--scope user`.

## Context budget

Codex lists installed skills within a small context budget (about 2% of the model's context window by default) and shortens descriptions first, then omits skills. With 39 skills installed, descriptions may be truncated. Options:

- Install only the skills a project needs: `--skills corporate-orchestrator,research-intelligence,product-discovery-prd,...`
- Raise `skills.max_context_tokens` in `~/.codex/config.toml` (up to 10,000 tokens).
- Invoke skills explicitly with `$skill-name`.

## Limits

- Codex has no sub-agent configuration format and no documented parallel delegation. The orchestrator role runs sequential specialist passes and must say so. Independent review means a fresh Codex session or turn under a reviewer role, not a separate agent.
- No per-role tool restrictions; Codex's own sandbox and approval modes are the controls.
- `agents/openai.yaml` metadata files are not shipped; they are optional and only affect UI presentation and implicit-invocation policy.
